# Make ownership changes explicit and Folia-safe

The kernel will use typed global, region, entity, and asynchronous execution contexts on Paper and Folia. Plug-in authors enter them through visible, non-suspending scoped calls, and context parameters may carry these temporary capabilities but not long-lived services. The kernel runs a block inline when the caller already owns its target; otherwise it schedules the block and suspends the caller until completion. Framework operations validate the current owner before using a context value, even if a callback captured it. Entity retirement returns a typed completion result, while task failures and parent cancellation keep their normal coroutine behavior. Ordinary plug-in tasks start on `Dispatchers.Default`, so server access must enter an ownership block. The safety guarantee covers framework execution APIs, not direct use of Paper schedulers or objects. This costs a few lines at call sites, but prevents ownership proofs from surviving suspension and keeps scheduler hops visible.
